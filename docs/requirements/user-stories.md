# ユーザーストーリー

見る人（[ペルソナ](./personas.md#見る人)）が何を達成したいかを書く。UI/UX の設計の入力にする。

## 書き方

```
### US-XX: [短い名前]
- ペルソナ:
- ストーリー: 〈ペルソナ〉として、〈したいこと〉。〈なぜなら〉
- 受け入れ条件:
- 段階:
```

## 人事

### US-01: 30秒で何者か分かる
- ペルソナ: 人事
- ストーリー: 人事として、スライドの QR からスマホで開き、30秒で何者か・主な実績を把握したい。限られた時間で次の選考に進めるか判断するため
- 受け入れ条件:
  - スマホの最初の画面に、名前・所属・実績3つが収まる
  - 初見の人の5人中4人以上が、30秒で何者か・主な実績を言える
- 段階: ①

### US-02: リンクのカードだけで誰か分かる
- ペルソナ: 人事
- ストーリー: 人事として、チャットや SNS で共有されたリンクのカードを見て、開く前に誰のサイトか分かりたい。社内で候補者を共有するため
- 受け入れ条件:
  - トップページとブログ記事に OGP 画像がある
  - トップページの OGP に名前・所属・実績が入っている
- 段階: ①

## 現場のエンジニア

### US-03: 判断の根拠まで辿れる
- ペルソナ: 現場のエンジニア
- ストーリー: エンジニアとして、作品や技術スタックから ADR まで辿り、判断の理由を確認したい。面接で深掘りする論点を決めるため
- 受け入れ条件:
  - 技術選定のすべてに ADR がある
  - サイトからリポジトリと ADR へのリンクがある
- 段階: ②

### US-04: このサイト自体の作りを見られる
- ペルソナ: 現場のエンジニア
- ストーリー: エンジニアとして、このページを返しているインフラの構成と、その稼働状況を見たい。言葉ではなく実物で実力を判断するため
- 受け入れ条件:
  - `/infra` に構成図と、目的から指標までの構造がある
  - 構成図は実際の構成から自動生成される
- 段階: ②

### US-05: 考え方を読める
- ペルソナ: 現場のエンジニア
- ストーリー: エンジニアとして、ブログ記事から考え方や問題の立て方を知りたい。一緒に働く姿を想像するため
- 受け入れ条件:
  - 既存の記事の URL が変わらない
  - 開発者ストーリーの記事がある
- 段階: ②
