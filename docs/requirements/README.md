# 要件

## 目的

このサイトを見たエンジニアが、この人と一緒に働きたい・話を聞きたいと思う。

就活で使うポートフォリオとして、誰がどの端末で開いてもすぐ読めることを前提に、UI/UX・開発体験（DX/AX）・インフラのすべてを作り込む。

## 成功の条件と指標

| 成功の条件 | 指標 | 目標 |
|---|---|---|
| 人事が30秒で何者か分かる | 初見の人が30秒で何者か・主な実績を言える割合 | 5人中4人以上（未計測） |
| エンジニアが掘ると根拠が出てくる | 技術選定のうち ADR がある割合 ／ `/infra`・ADR までの到達率 | 100% ／ 推移を計測 |
| いつでも誰でも速く見られる | Lighthouse（モバイル）4項目 ／ LCP（実測 p75） ／ 月間稼働率 | すべて100 ／ 1.5秒未満 ／ 99.9% |
| 作り方そのものが証拠になる | main へ push してから本番に出るまで ／ 手作業のデプロイ・インフラ変更 | 10分以内 ／ 0回 |
| 就活軸と作りが同じ話になる | 就活軸5項目それぞれに対応する証拠がサイトにある | 5／5 |
| 名前から本人のサイトに辿り着ける | 「藤井優気」「wisteriahuman」での Search Console の平均掲載順位と、同条件で手動検索した自然検索順位 | 「藤井優気」で自然検索1位。「wisteriahuman」も継続観測（未計測） |
| AI の説明から本人の情報を確かめられる | Google の AI による概要の有無・本人説明の正確さ・このサイトへの参照リンクを手動確認 | 概要が出た場合、このサイトを参照して本人を正しく説明（未計測） |

目的の達成は、面談・面接でサイトに触れられた回数と、サイト経由の連絡の件数を手で記録して測る。

計測は Cloudflare Web Analytics（Cookie なし）と外部の稼働監視を使い、費用は0円に保つ。

検索の登録・観測は [検索と AI の公開後の確認](../guides/search-and-ai.md) に従う。索引登録・順位・AI による概要の表示や引用は保証されず、実装の検査に合格したことと検索での達成を区別する。

## 制約

- 日本語のみ（→ [ADR-005](../adr/adr-005-japanese-only.md)）
- インフラ費用は月1,000円まで（現状0円）
- 自宅の k8s を主とし、Terraform で宣言的に管理する。学ぶクラウドは AWS（→ [ADR-006](../adr/adr-006-hosting-direction.md)）
- サービスを止めずに移行する。既存ブログの URL は維持する。OGP は作り変えてよい
- 技術選定はすべて ADR に残し、理由を説明できる状態にする

## こだわりの優先順位

ぶつかったときは次の順に守る。どの軸も手を抜くわけではなく、迷ったときにどれを先に守るかの順番。

1. 誰でも見られる（速さ・アクセシビリティ）
2. 中身が伝わる
3. インフラと開発体験の作り込み
4. 見た目の演出

## 構成の方針

- 構造は読みやすく普通に。何者か → 何ができるか → 実績 → 根拠
- 驚きは「サイトそのものが証拠になっている」一点に集める。具体案はアイデアソンで詰める
- 見せる作品：ハッカソン4件・学内のチーム開発（FUN Developers Hub）と `/infra`
- 目標の構造の置き場所は [ADR-008](../adr/adr-008-goal-visibility.md) を参照
