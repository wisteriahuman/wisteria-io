# ペルソナ

このサイトには「見る人」と「開発する人」の2種類の利用者がいる。見る人のためにユーザーストーリーを、開発する人のために開発者ストーリーを書き、それぞれ UI/UX と、アーキテクチャ・開発体験の設計の入力にする。

## 見る人

### 人事

| 項目 | 内容 |
|---|---|
| 来る経路 | ES・スライド・イベントの QR コード |
| 端末と時間 | スマホで30秒〜1分 |
| 技術の知識 | 用語は知っているが、コードは読まない |
| 知りたいこと | 何者か・実績・人柄 |
| 成功の状態 | この人に会いたいと思い、次の選考に進める |
| 妨げになること | 実績が下に埋もれている、専門用語が並ぶ、表示が遅い |

イベントの参加者（学生・企業の人）も、スマホで短時間見るという点で同じ見方をするため、このペルソナに含める。

### 現場のエンジニア（面接官）

| 項目 | 内容 |
|---|---|
| 来る経路 | 面接前の準備。ES やスカウトのリンク |
| 端末と時間 | PC で10〜20分 |
| 技術の知識 | 設計・インフラの判断を評価できる |
| 知りたいこと | その判断は本人のものか、深掘りしても根拠が出てくるか |
| 成功の状態 | 面接で聞きたいことが具体的になっている |
| 妨げになること | 判断の理由が書かれていない、リポジトリが整理されていない |

## 開発する人

### 自分

| 項目 | 内容 |
|---|---|
| 役割 | 一人で企画・設計・運用まで担う |
| 環境 | Neovim とターミナル中心。開発環境は Nix で管理。Mac と Linux（surface）を併用 |
| 時間 | 就活中で作業時間は細切れ。数日〜数週間あくこともある |
| 進め方 | 判断は自分、手を動かすのは AI エージェント |
| 良い体験 | 思いついたことを短い手順で本番まで出せる。間があいても判断の経緯を思い出せる |

### AI エージェント

| 項目 | 内容 |
|---|---|
| 役割 | もう一人の実際の開発者。実装・ドキュメントの下書き・検証を担う（Claude Code・Superpowers） |
| 知識の状態 | 会話をまたいだ記憶を持たない。毎回ドキュメントとコードから状況を読み取る |
| 制約 | 判断の根拠がドキュメントにないと、推測で埋めてしまう |
| 良い体験（AX） | ドキュメントとコード構造から、迷わず正しい場所を見つけて変更し、自分で検証できる |

AI エージェントを開発者ペルソナとして扱うのは、実際にこのサイトの多くを AI エージェントが書くため。AX（Agent Experience）はもともと「AI エージェントがサービスや API を使いやすいか」を指す言葉だが、ここでは「AI エージェントがこのコードベースを変更しやすいか」に広げて使う。
