# ドキュメントの書き方

## 目的
判断の経緯を、自分・AI エージェント・面接官の誰が読んでも辿れるようにする（→ [ADR-004](../adr/adr-004-documentation-structure.md)）。

## ルール
- 判断を伴う変更には、ADR の追加・更新を伴わせる
- 新しい文書は、そのディレクトリの `TEMPLATE.md` をコピーして作る
- ADR は `adr-XXX-<内容>.md` の連番で命名し、`adr/README.md` の一覧に追加する
- ADR の「検討した別の選択肢」と「受け入れるトレードオフ」を空にしない
- 決まっていないことは「提案中」「下書き」と明記し、決まったものと区別する
- このリポジトリは公開されている。選考中の企業名・日程、選考上の目標、個人的な事情は書かない
- 表の層（サイト本体）では KGI・KSF などの用語を使わず、普通の言葉で書く

## 良い例

```
## 検討した別の選択肢 (Alternatives Considered)
- **bun**: インストールが速いが、Astro の実行は Node のままで二重構成になる
```

## 悪い例

```
## 検討した別の選択肢 (Alternatives Considered)
- 特になし
```

## 例外
- 誤字の修正など、判断を伴わない変更には ADR は要らない
