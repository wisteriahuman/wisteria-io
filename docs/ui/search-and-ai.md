# 検索から本人を知り、AI に内容を聞く

## 利用者と主タスク

名前から訪れた人が、実名・読み・ハンドル・所属を見て本人だと確かめる。詳しく知りたい人は記事やサイトの内容を外部 AI に質問できる。要件は本人との合意済み事項に基づく（ADR-019）。

## 画面と遷移

- トップの名前の直下に読み・wisteria・wisteriahuman を表示する。
- トップのリンクの紙に「このサイトを AI に聞く」を1か所置く。`Links.astro` は別作業の対象のため、ページから独立した `AskAI.astro` を呼ぶ。
- 記事の本文の後に著者名とトップへのリンク、続けて「この記事を AI に聞く」を1か所置く。
- Claude と ChatGPT の通常のリンクで同じタブに移動する。サイト全体は `/llms.txt`、記事はその記事の本番 URL を質問文に含める。URL をエンコードし、本人の操作で外部サービスを開く。
- 外部サービスからはブラウザの「戻る」で戻れる。質問文が開く旨と、元ページで回答を確かめる案内を添える。

## 実績の出典への移動

作品の既存の関連リンクは、公開元の開催・受賞報告だと分かる名前で表示する。各作品には `project-<id>` のアンカーを持たせ、AI向け案内からその作品へ直接移動する。新しい入力・画面は追加しない。

## 状態

静的 HTML のためサイト内の読み込み・入力・空・エラー・権限状態はない。外部サービスのログイン、取得不可、回答不能はサービス側の状態であり、質問文にも取得できない場合の説明を求める。記事一覧の生成では下書きを除く。

## 見た目

ADR-016 の紙と罫線、既存のペン色と下線を使う。本文の行高は 1.75rem。リンクは上下に半行ずつ余白を置いて高さ3.5remを確保し、狭い画面では折り返す。JavaScript を追加せず、キーボードで普通のリンクとして操作できる。

## Pro Max 参照

`ui-ux-pro-max` の `static component links --stack astro` で得た「静的内容は .astro を使う」を採用。検索結果の対象は Astro 7 だが、この原則は既存の Astro 5 の部品構成とも一致する。`external link accessible name --domain ux` はボタン向けの結果だったため採用せず、既存の文字リンク・フォーカス表示に従う。罫線・リフローは `pnpm check:grid`、アクセシビリティは既存の Lighthouse で検証する。
