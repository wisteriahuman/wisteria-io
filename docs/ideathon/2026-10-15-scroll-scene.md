# アイデアソン: スクロールで動く場面（段階②-a）

- 日付: 2026-10-15
- テーマ: 画面に固定した図がスクロールに合わせて変わる場面を、サイトの1か所にだけ作る。動きに意味があり、CSS だけ（`position: sticky` と scroll-driven animations）で作れて Lighthouse 100 を崩さず、人事のスマホ30秒の邪魔をしない
- きっかけ: [animejs.com](https://animejs.com/) のような、スクロールで図が動くページ
- 進め方: `ideathon` スキル。[前回](./2026-10-15-design.md)で使わなかった6つの視点で発散した。印は付けずに終え、採る案を決めた

## 採った案

| 扱い | 案 | 理由 |
|---|---|---|
| 採る | 128 手を離れる道具 + 130 一人から全員への引き絵（About の入口） | 作ったものから作者の手が離れ、使う人が増え、視点が全員まで引いて KGI「みんなの役に立つ」に着き、そのまま KSF・KPI の樹形図へつながる。4つの視点から同じ形が出た。事実（学内で作ったものが手を離れても使われている）に支えられ、専門用語なしで伝わる。驚きの一点（作りの証拠）は案3「この部分の作り」が担うため、この場面は人柄に使う |
| 後に回す | 101 検証の関門 + 106 ハンコの稟議書 | 「AI が書き、機械が確かめ、判断は本人」を一枚で見せられるが、トップでは案3と同じ証拠を二度見せることになる。`/infra` の入口に置く（段階②-d） |
| 採らない | 123 ルンバ | 自宅から予備への切り替えは段階②-c まで無く、まだ無い仕組みを見せることになる |
| 採らない | 122 飾るほど点数が落ちる | 飾りを実際に画面に出すことになり、言いたいことと逆になる |
| 採らない | 118 merge がセーブ地点 | 過去の見た目の再現に版ごとの CSS が要り、重くなる |

- 使う人を表す点は抽象的に描き、人数を表すものに見せない（利用者数は持っていない）
- 動きを減らす設定や対応しないブラウザでは、最後の状態（KGI と樹形図）を静止して出す

## 既出
- 128・106: 同じものは見つからず
- 130 に近い型: 手前の内容を固定し、後ろの層がズームアウトする型。価値観を見せるのに向くと紹介されている（[UX Planet](https://uxplanet.org/i-noticed-a-pattern-in-page-scroll-animation-on-websites-78d0c021b537)）

## 全案

前回と番号が混ざらないよう、101 から振った。`*` は確率の低い案。括弧は出どころの視点。

**1つの変更が、関門を通って本番に出るまでを見せる**
101. 検証の関門を進む — PR の駒が型検査 → リント → ビルド → Lighthouse を1つずつ通り、途中で一度落ちて直してから merge に着く（遊び・物流・極小）
102. 本番までの区間タイム — PR → 各検証 → merge → 本番の区間が点き、最後に合計の時間が出る（ゲーム）
103. squash の荷台 — 小さなコミットの箱が1台の荷台にまとまって main へ出ていく（物流）
104. 1つの PR の一生 — Issue・AI の下書き・本人の判断・検証・merge・本番を、図が順に姿を変えて見せる（極大）
105. この場面の CSS が自分を説明する — この場面自体の CSS が並び、今効いている行が光る（極大）

**AI と本人の分担を、動きで見分けさせる**
106. ハンコの稟議書 — 機械の印が押され、最後の決裁欄にだけ本人の印が押される（遊び）
107. AI とのバトンリレー — AI の区間は長いが、ゴールテープを切るのは本人（遊び）
108. 配送員と検品台 — AI が運び込んだコードを、本人が検品台で通すか止める（物流）
109. 朱色の一行 — AI の行が灰色で積み上がり、本人が決めた行にだけ朱色の判が残る（極小・商い）
110. 2人協力プレイの入力履歴 — 2P（AI）の入力と、1P（本人）の採る・却下するボタンが交互に光る（ゲーム）

**判断が変わっていく・捨てた案が消えていく**
111. 捨てた枝が消える分岐図 — 採らなかった枝が理由を残して消え、採った1本が太く残る（極大・ゲーム）
112. 書き直される一文 — 「何を作るか」の一文に、取り消し線と書き直しが3回重なる（極小）
113. 一行ずつの PR 差分 — 実際の差分で、赤い行が消えて緑の行が入る（極小）
114. 名前の改名履歴 — 関数名が書き換わり、その都度の理由が添えられる（遊び）
115. 返品された判断 — 一度出した ADR が返品され、理由を書き足して出し直される（物流）
116. ADR カード図鑑 — ADR がカードのようにめくれ、却下した案の数がレア度になる（遊び）
117. *引き算の舞台 — 詰まった図から部品が1つずつ消え、芯だけが残る（極小）
118. merge がセーブ地点 — スクロールを戻すと、サイトの見た目も前の版に巻き戻る（ゲーム）
119. 在庫を持たない作品棚 — 注文（課題）が入ってから部品が集まり、作品が組み上がる（物流）
120. 相手で描き変わる設計 — 審査員向け → 使う人向け → 引き継ぐ後輩向けと、作品の図が描き変わる（商い）
121. 優先順位の付箋 — 速さ・中身・インフラ・演出の付箋が優先順位どおりに並び直す（極小）
122. *飾るほど点数が落ちる舞台 — 装飾が足されるたびに Lighthouse の円が欠け、外すと100に戻る（極大）

**配信が止まらない仕組みと、届くまでの道**
123. *自宅サーバーとルンバ — お掃除ロボットが電源タップにぶつかって止まり、予備に切り替わって紙面は出続ける（遊び）
124. 残機が減っても続く — 自宅の k8s が落ちても、AWS が引き継いでページは止まらない（物流・ゲーム）
125. 配信経路の断面図 — 1本のリクエストが、スマホ → 家の回線 → 自宅の k8s → 予備の AWS へ降りていく（極大）
126. 最後の一区間はスマホの手元 — 荷物が軽くなり、JS も重い画像も積まずに手元に着く（物流）
127. 配信の天秤 — 自宅と予備の天秤に、費用・止まる確率・学べることの重りが載る（商い）

**手を離れても使われ続ける（みんなの役に立つ）**
128. 手を離れる道具 — 作者の手が離れ、名前が薄れるのと入れ替わりに、使う人の点が増え続ける（物流・商い・極大・極小）
129. *主人公がいなくなっても動く町 — 主人公が去っても、町の人は道具を使い続け、時計が進む（ゲーム）
130. 一人から全員への引き絵 — 1人の利用者から研究室・大学・街・全員へと引き、最後に KGI が収まる（極大）

**考える手順と、積み上げてきたもの**
131. 計算量が畳まれる一問 — 全探索の木が刈り込まれ、O(n²) が O(n log n) に畳まれる（極小・極大）
132. 一周ごとに速くなる提出の輪 — 提出 → 不正解 → 直す → 正解の輪が、回るたびに短くなる（ゲーム）
133. *色の坂を登る — AtCoder の色の坂を人影が登り、受賞や ICPC が足場になる（遊び・ゲーム）
134. ICPC の風船 — 受賞や ADR が色ごとの風船として上がる（遊び）
135. *自分の決算書 — 投じた時間 → 得た資産 → 配当と埋まり、最後の行に KGI が置かれる（商い）

**見る人の手元に、受け取ったものを積む**
136. 30秒の領収書 — スクロールした分だけ実績が1行ずつ印字され、最後に合計が出る（商い）
137. 質問の先払い — 面接で聞かれそうな質問の札が裏返り、答えの ADR の番号が出る（商い）
138. *ポイントカード — 読み進めると判子が押され、「この人に聞くと面白い話1つ」の引換券に変わる（商い）

## 使った視点
遊び・極小・極大・商い（価値系）、物流・ゲーム（遠方系）
