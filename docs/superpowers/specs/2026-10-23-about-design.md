# About を、経験の年表だけにする（段階②-a の E）

- 日付: 2026-10-23
- 置き換える部分: [2026-10-15 の仕様](./2026-10-15-redesign-design.md)の「E. About」と、[詳細設計](../../design/redesign.md)の About の樹形図・スクロールで動く場面

## 意図
About まで読みに来る人に、本人の経験を事実だけで見せる。読んだ人が「この続きを本人に聞きたい」と思い、話しかけられるようにする。

前は、人生の KGI・KSF・KPI の樹形図と、スクロールで動く場面を置く予定だった。本人が考え直し、次の理由で外した。
- ポートフォリオで性格や価値観を語りすぎると、痛く見える。本人の条件は「普通に見られても恥ずかしくない」こと
- 価値観の根っこは、相手が知りたいと思ったときに会って話す方がよい（本人の考え）。About に書き切らない方が、聞きたい余白も残る

## 誰が読み、何が起きれば成功か
- 読む人は、時間をかけて About まで降りてくる人。選考の相手（人事・面接官）に限らず、イベントで会った人、X・GitHub から来た人、一緒に作る仲間になりうる人も含む
- トップの最初の画面は「30秒で何者か」に合わせてあり、変えない
- 成功: 読んだ人が、本人に聞きたいことを一つ以上持つ。そして、どこで話しかければよいかが分かる

## 守ること
- 書いた行が自分の評価になっていない。初めて読む人から「痛い」「狙っている」と言われない

## やること

### About の紙（`src/components/About.astro`）
中身は経験の年表だけにする。時期と一行ずつ、事実だけを書く。

| 時期の欄 | 行 |
|---|---|
| 小学校〜高校 | ハンドボールをやっていた |
| 2024 | 大学でプログラミングを始める |
| 2025 | ICPC 2025 アジア横浜大会に出場 |
| 大学 | 次の三つを、この一つの欄の下に並べる |

「大学」の欄の下に並べるもの:
- 競技プログラミング（AtCoder の色）
- エディタを Neovim に、開発環境を Nix にする
- マシンごとの OS の遍歴（下の小さな一覧）

- **時期の欄**: 経歴の紙と同じ `.margin-note` を使う。768px 以上では紙の左の日付の欄に、スマホでは行の上に出る。分かる年は年で書く。分からないものは「大学」の欄を一つだけ置き、その下に入れ子で並べる（本人の決定）。`.margin-note` は4つになる
- **マシンの一覧**: 大学の中の小さな一覧にする。中身は今の3台のまま。今ある添え書き（「入学時の推奨機」「マウスコンピューター」「今の普段使い」）も残す（Claude の判断）
  - Surface: Windows → Ubuntu → CachyOS → Garuda → 今は Ubuntu Server
  - DAIV: Pop!_OS → コーヒーをこぼして故障
  - MacBook Air・Mac mini: 今の普段使い。Mac mini はこのサイトの配信も担当
- **AtCoder の色**: `src/data/profile.ts` の `ratings` にある値（今は「AtCoder 水色」）を使い、最初の画面と同じデータから出す
- **年表の中身**: データとして `src/data/` に置くか About.astro の中に書くかは、作る人が決めてよい。今の `machines` の配列と同じく、About.astro の中で足りる
- **見出し**: 今の「About」（手書きの書体・蛍光ペン）のまま
- **この部分の作り**: 今のまま。ADR-008・ADR-016、About.astro を指す

### 外すもの
- 今の About の段落をすべて外す。外すのは次の三つ
  - 「公立はこだて未来大学 システム情報科学部…。バックエンド開発と競技プログラミングが好きです。」
  - 「API設計やDB設計を考えるのが楽しくて…。最近はAI/LLMを組み込んだプロダクト設計にも興味があります。」
  - 「エディタは Neovim。開発環境は Nix で管理しています。マシンごとの OS の遍歴はこんな感じです。」（中身は年表に移る）
- 人生の KGI・KSF・KPI、樹形図、`src/data/goals.ts`（作らない）
- スクロールで動く場面
- 性格・価値観・核の話。「なんとなくで終わらせない」などの一文も書かない
- ハンドボールの詳しい戦績（全国選抜・インターハイ・東北大会）、大学でハンドボールをやめた話、保育園の話
- 困った・試した・結果の話（OS を変えた理由など）

### リンクの紙（`src/components/Links.astro`）
- シールの下に一行、「話しかけるなら X の DM へ」と書く。リンク先は `src/data/profile.ts` の `socialLinks.x`（シールと同じ値。PR #18 で main に入った）
- 行の高さは罫線の 1.75rem にそろえる

### 重なりについて（決めたこと）
- 経歴の紙のハンドボールの行（不来方高等学校 ハンドボール部 GK）は残す
- AtCoder・ICPC は最初の画面と経歴にも出るが、年表にも入れる（本人の判断）
- 「大学からプログラミングに触れる」（経歴）、Neovim・Linux（スキル）とも重なるが、年表では時間の流れとして見せる

## 確かめ方
- `pnpm verify` が通る（型・リント・ビルド・ビルド結果の検査・罫線の検査・単体の検査・Lighthouse）
- `scripts/check-dist.mjs` を直す。今の About の検査（「3年」を含まない、「Ubuntu Server」を含む）は残す。次を足す
  - About に KGI・KSF・KPI の語が無い
  - About に年表の時期の欄（`.margin-note`）がある
  - About の AtCoder の色が `ratings` の値と同じ
  - リンクの紙に「話しかけるなら X の DM へ」がある
- `scripts/check-grid.mjs` で、全幅・文字の大きさ 16/20px で罫線に乗っている
- 下書きができたら、初めて読む人の役のエージェント（人事・エンジニア・大学の友人の3人）に、ビルドした About を読ませる。答えさせるのは次の三つ
  - 「痛い」「狙っている」と感じた行
  - 本人に何を聞きたくなったか
  - どの行でそう思ったか
- 聞きたいことが一つも出なければ、作る人はそこで止め、本人に結果と直す案を渡す。表にない事実を足すことや、行を自分の判断で入れ替えることはしない（Claude の判断。載せる事実を選ぶのは本人なので）。「痛い」の指摘で言い回しを平らにするだけなら、作る人が直してよい
- 最後は本人が staging で読んで決める。PR を作ったら止まり、本人の OK の後にマージする（見た目と文章の読み心地が変わる PR なので、`docs/guides/development-flow.md` の「本人が触って確かめる必要のある PR」にあたる）

## 作る人に任せること
- 年表のマークアップ（`<ol>` と `.margin-note`。経歴の紙と同じ形が自然）
- マシンの一覧の入れ子の形と、時期の欄の正確な言い回し（「小学校〜高校」「小〜高」など）
- check-dist の検査の書き方
