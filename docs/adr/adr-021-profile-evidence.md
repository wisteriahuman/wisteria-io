# ADR-021: 本人の実績を公開元の報告と対応付ける

- ステータス: 採用
- 日付: 2026-10-26

## 背景・課題 (Background/Problem)

- 同音の別人が検索のAI概要に混在する。既存の実名・読み・ハンドル・所属と、確認できる実績を一貫して参照できる必要がある。
- FISH優勝の関連リンクが移転して404になっていた。大学の現行報告には本人の実名・チーム・優勝が記載されている。
- AI向け案内の作品リンクがすべて同じ作品一覧を指し、個別の作品を直接参照できなかった。

## 決定事項 (Decision)

- 大学の現行記事へリンクを修復し、本文のリンク名を公開元と開催・受賞報告が分かる表記にする。
- 公開元の報告を作品データのreportとして持ち、本文・Person.subjectOf・llms.txtで共用する。
- 本人のアカウントはsameAs、本人についての他者の文書はsubjectOfとして区別する。大学ニュースを本人アカウントに見立てない。
- 各作品に安定したアンカーを付け、llms.txtから該当作品へ直接移動できるようにする。
- 本人情報や実績は既存データのまま。大学の記事は開催・受賞の根拠であり、開発担当や技術選択の詳細まで大学が保証したとは扱わない。

### 理由 (Reasons)

- 人にも検索システムにも、名前と確認可能な実績の対応を示す。出典が壊れた状態では検証できない。
- GoogleのAI機能に特別なマークアップは要求されていない。独自のAI向け指示ではなく、本文の根拠と通常の構造化データの整合を改善する。

### 受け入れるトレードオフ (Accepted Trade-offs)

- 外部サイトの移転はビルドだけでは検知できない。定期的に外部の報告を開いてリンク先と内容を確かめる。
- subjectOfやllms.txtを用意しても、AI概要に採用されること、本人への説明や引用の安定は保証されない。
- リンク名は長くなるため、小さい画面では折り返す。既存の行高と罫線検査で確認する。

## 検討した別の選択肢 (Alternatives Considered)

- **llms.txtだけ増やす**: 入口を作れるがGoogle検索への特別な入力ではなく、本文の壊れた根拠も残る。
- **FAQや自己紹介を大量に追加する**: キーワードを増やせるが、既存の情報を繰り返し、読者の確認の負担が増える。
- **大学の記事をsameAsへ追加する**: 手軽だが、本人プロフィールと本人を含む報告は別物なので不適切。

- SEOのURL修正に加え、本人の実績の出典へ到達できることをGEOの具体的な改善対象にした。通常検索1位だけで、AI概要の本人説明と引用まで達成済みとは扱わない。
