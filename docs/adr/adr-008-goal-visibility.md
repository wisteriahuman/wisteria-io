# ADR-008: About に人生の目標の構造を出さず、経験の事実を並べる

- ステータス: 採用
- 日付: 2026-10-15（2026-10-23 に「目標の構造をどこまで見せるか」から改訂）

## 背景・課題 (Background/Problem)
- About まで読みに来るのは、時間をかけて下まで降りてくる人。選考の相手に限らず、イベントで会った人、X・GitHub から来た人、一緒に作る仲間になりうる人も含む
- 読んだ人が「この続きを本人に聞きたい」と思い、どこで話しかければよいかが分かれば、About は役目を果たしている
- 一方で、ポートフォリオで性格や価値観を語りすぎると、痛く見える。本人の条件は「普通に見られても恥ずかしくない」こと
- 選考上の目標をそのまま見せると、見る企業に「数ある応募先の一つ」と読まれる

## 決定事項 (Decision)
- 人生の目標の構造（KGI・KSF・KPI）は About に出さない。About には経験の事実だけを、時期と一行ずつの年表で並べる
- 年表に自分の評価（性格・好き・楽しい など）を書かない。価値観の根っこは、相手が知りたいと思ったときに会って話す
- 話しかける先として、リンクの紙に「話しかけるなら X の DM へ」の一行を置く
- このサイトの目的 → 成功の条件 → 指標は要件書（`requirements/README.md`）に残す。`/infra` では指標の数字だけを見せ、KGI という言葉は使わない
- 選考上の目標はどこにも出さない

### 理由 (Reasons)
- 事実だけなら、読む人が自分で解釈できる。評価を書いた行は、その人の評価と食い違ったときに痛く見える
- 価値観まで書き切ると、読んだ人に聞くことが残らない。事実の並びで止めた方が、聞きたい余白が残る
- 聞きたくなった人が、その場で話しかけられる先があれば、読んだことが会話につながる

### 受け入れるトレードオフ (Accepted Trade-offs)
- 考え方の筋道は About からは伝わらない。会って話すまで、価値観は読む人に届かない
- 年表は経歴・最初の画面と重なる行（AtCoder・ICPC）がある。年表では時間の流れとして見せる

## 検討した別の選択肢 (Alternatives Considered)
- **人生の KGI → KSF → KPI を見出しで出す（2026-10-15 の決定）**: 筋道は見えるが、ポートフォリオで性格や価値観を語りすぎて痛く見える。書き切ると、聞きたい余白も残らない
- **根っこの考えを、開いた人だけが読む層に置く**: 表は平らになるが、書いてあることには変わらず、会って話す余白が減る
- **今の段落（好きなこと・興味）のまま**: 「好き」「楽しい」は自分の評価で、事実ではない
- **すべて非公開にする**: About に何も無いと、聞くきっかけも無くなる

## 議論 (Discussion)
- 最初は人生の目標を外に出さない案だったが、「ポートフォリオは人物を見せる場所」という指摘で逆にした
- 2026-10-14: 最初は「2つの構造（人生とこのサイト）を同じ形にそろえる」とし、KGI・KSF の用語は表に出さないとしていた
- 2026-10-15: このサイトの KGI は表に出さなくてよく、人生の KGI・KSF・KPI は用語ごと出した方が納得感がある、と判断し直した。「同じ形にそろえる」は外した
- 2026-10-15: KGI は「みんなの役に立つ」。最初の下書き「考え抜くことで、より大きな課題を解決できる人になる」は在り方（KSF）を KGI の位置に置いていたため浅く感じた
- 2026-10-23: 本人が「KGI・KSF などは入れる予定だったけど、入れなくていいなって今思いました」と考え直した。先にポートフォリオとしての勝ち（読んだ人が本人に聞きたくなり、話しかける先が分かる）を決め、その上で About に置くものを経験の事実だけにした。本人の条件は「普通に見られても恥ずかしくない」「性格の話をしすぎると痛い奴になる」。ハンドボールは「やっていた」程度にし、戦績は書かない。KGI・樹形図・スクロールで動く場面は外した
