# サイトの作り直し（段階②-a）

## 目的
表は30秒で読める普通の自己紹介のまま、その下に「このサイトそのものが作り方の証拠」になっている層を置く。人事はスマホで最初の画面だけで何者か分かり、面接官は気になった場所から、その部分を決めた PR・ADR・コードまで降りられる。

### Non Goals
- 配信基盤の移行（段階②-c）
- `/infra` の構成図と稼働状況（段階②-d）
- 毎日自動で書き換わる数字（アイデアソンの案42は採らない）
- 閲覧の記録を本人に返す仕組み（案17・18は採らない）

## 背景
- 段階①で中身と最初の画面を作り直した（→ [トップページ（段階①）](./top-page.md)）
- アイデアソンの記録: [デザイン](../ideathon/2026-10-15-design.md)・[スクロールで動く場面](../ideathon/2026-10-15-scroll-scene.md)
- 人生の KGI・KSF・KPI の中身は grilling で決めた（→ [ADR-008](../adr/adr-008-goal-visibility.md)）
- 「この部分の作り」に出す PR は、main の squash のコミットの件名の末尾 `(#N)` から、ファイルごとの `git log` で拾える。GitHub の API は使わない

## 概要
見た目は「明るい紙」にする。生成りの地に罫線、見出しは明朝、本文はゴシック、角は少し丸める。トップは1枚のまま、最初の画面 → 経歴 → 作品 → スキル → About → リンクの順を保つ。

各セクションの右下に「この部分の作り」を置く。開くと、そのセクションを決めた ADR、コードのファイル、そのファイルを変えた最近の PR 3件が出る。JS は使わず `<details>` で作る。ブログの記事の末尾にも「この記事の履歴」を置く。

About の入口に、スクロールで動く場面を1つだけ置く。作ったものから作者の手が離れ、使う人が増え、視点が全員まで引いて「みんなの役に立つ」（人生の KGI）に着き、そのまま KSF・KPI の樹形図につながる。

作品ごとのページ（`/works/<名前>`）を作り、面接官が掘る入口にする。本番の前に見た目を確かめるため、PR ごとの確認用の環境（staging）を用意する。

## 設計詳細

### 利用者と主タスク
- 人事: スマホで30秒〜1分。最初の画面で名前・所属・実績3つを読み、読み終えたら社内に回す
- 現場のエンジニア: PC で10〜20分。気になった場所の「この部分の作り」や作品ページから、判断の根拠を掘る
- 自分: PR を出し、staging で見た目を確かめてから merge する

### 画面と遷移

**トップ（`/`）**
1. 最初の画面: 名前・所属・実績3つ・評価・リンク（段階①の中身のまま）
2. 経歴
3. 作品: カード全体が作品ページへのリンク
4. スキル
5. About: スクロールで動く場面 → 人生の KGI・KSF・KPI の樹形図 → 根底の段落
6. リンク: 外部リンク、社内転送用の一行、AI エージェント向けの説明

各セクションの右下に「この部分の作り」（`<details>`）。

**About の樹形図**
- 中身は入れ子のリスト（KGI → KSF 3つ → それぞれの KPI）。CSS で木の図に見せる。PC は横に枝分かれ、スマホは縦
- KGI: みんなの役に立つ
- KSF: 新しいことを吸収し続けて成長し、成果を出す／理念が日々の行動にまで表れている人たちと働く／考え続ける
- KPI: 受賞・FISH で作ったものが今も大学で使われていること（1つ目）、このサイトの全変更が自動検証を通っていることと最新の PR（2つ目）、AtCoder 水色・ICPC 2025 横浜・ADR の本数（3つ目）
- 根底の段落（考える葦、幸せになってほしいという気持ち）は、本人が自分の言葉で書く。書けるまでは置かない

**スクロールで動く場面（About の入口）**
- `position: sticky` の舞台に、作ったものの図を置く。スクロールに合わせて、作者の手が離れ、使う人の点が増え、視点が大学 → 街 → 全員へ引き、最後に KGI の文字が収まる
- 使う人の点は抽象的に描き、人数を表すものに見せない
- CSS の scroll-driven animations だけで作る

**作品ページ（`/works/<名前>`）**
- 上に「作品一覧に戻る」（トップの該当カードの位置へ）
- 順番: 何を作ったか・誰のためか → 自分の役割 → 結果 → 判断（技術選定とその理由、捨てた案）→ リンク（GitHub・デモ）→ この部分の作り
- 中身の無い項目は見出しごと出さない
- 文章は、事実を確かめてから書く。各作品のリポジトリ（README・コミット）で確かめ、確かめられないことは書く前に本人に聞く。チームの作品での役割は、本人が決める

**ブログ**
- 一覧と記事は新しい見た目に合わせる。URL は変えない
- 記事の末尾に「この記事の履歴」（記事のファイルを変えた PR）

**AI エージェント向けの説明**
- `/llms.txt` をビルド時に `src/data/` から作る
- リンク欄に「AI エージェント向けの説明」として `/llms.txt`、リポジトリの `CLAUDE.md`・`docs/` へのリンクを並べ、AI エージェントもこのリポジトリの開発者であることを一言添える

**社内転送用の一行**
- リンク欄に「共有」ボタン。スマホは共有シート（`navigator.share`）、PC は文をコピー
- 文面は `src/data/profile.ts` の要約から作る: 「藤井 優気（28卒・公立はこだて未来大学）Go College ベストエンジニアリング賞・ハッカソン受賞3回・ICPC 2025 横浜 https://wisteria-io.com」

**staging**
- このリポジトリから出た PR（fork でないもの）は、verify が通ったら `staging.wisteria-io.com` に出す。最後に verify を終えた PR で上書きする
- staging は検索に載せない（noindex）
- fork からの PR は、今まで通り自宅の機械で動かさない

### 一覧
- 作品カード: カード全体が作品ページへ。並び替え・絞り込みは5件のため置かない
- ブログ一覧: 今の並び（新しい順）のまま

### 入力
- 入力欄は無い。ボタンは「共有」だけ

### 状態
- 静的なページのため、読み込み中・エラー・権限なしは対象外
- 「この部分の作り」で PR がまだ無い: 「まだ変更の記録がない」と出す
- 作品ページで項目の中身が無い: 項目ごと出さない
- JS が無い: 「共有」ボタンの代わりに文そのものを出す
- 動きを減らす設定・scroll-driven animations に対応しないブラウザ: 動く場面は最後の状態（KGI と樹形図）を静止して出す

### 見た目
- 新しくする。紙の質感（ui-ux-pro-max の E-Ink / Paper を元にする）
  - 生成りの地、墨色の文字。罫線は最初の画面ではっきり、ほかでは薄く
  - 見出しは明朝、本文はゴシック（日本語は端末のフォント、ADR-009）
  - 角は 6〜8px 丸める。チップは線ではなく薄い面
  - 明るい紙だけにし、ダークは作らない
- 動き: セクションが画面に入るときに少しだけ出る（CSS のみ）、スクロールで動く場面は About の1か所だけ

## 検討した別の選択肢
- **スイス・ミニマル（白地・黒の罫線・等幅の見出し）**: 表が一番普通に見えるが、角張った線が初期表示のように見え、作っていない印象を与える
- **今の暗い配色の延長**: 無難だが、よく見る形
- **樹形図を SVG の木で描く**: PC では見栄えがよいが、スマホ幅では文字が小さくなるか横スクロールが出て、文言を変えるたびに改行を手で直すことになる
- **スクロールでスライドのように1画面ずつ切り替える**: 1画面に収まらないセクションが読めなくなり、30秒で流したい人事の邪魔になる
- **「この部分の作り」を全体のスイッチで出す**: JS が要り、最初の画面を選ばせる手間も増える
- **About を別ページにする**: 人事が読む前に離れる
- **develop ブランチで staging を作る**: squash で merge するたびに履歴がずれ、衝突しやすくなる

## 注意点・懸念事項
- 紙の地での文字と罫線のコントラスト（4.5:1）を、`pnpm verify` の Lighthouse と目視で確かめる
- CI のチェックアウトを深くし（`fetch-depth: 0`）、ファイルごとの PR を拾えるようにする。ビルドが少し遅くなる
- scroll-driven animations は Firefox が既定で未対応。未対応でも最後の状態が出るので、中身は欠けない
- 作品ページの文章は、チームの成果を自分の成果として書かない
- インターン先の社内のことは書かない

## Pro Max 参照
- Reduced Motion（High）: `prefers-reduced-motion` を確かめ、動きを止める
- Touch Target Size（High）: Web は WCAG の Target Size に従う。隣接するリンク・チップの間隔は 8px 以上（段階①から継続）
- Contrast Readability（High）: 明るい地には濃い文字。灰色の地に灰色の文字を置かない
- Heading Line Balance（Medium）: 見出しの改行を `<br>` で固定せず、幅とフォントを変えて自然な折り返しを確かめる
- スタイル: E-Ink / Paper（ダークは非推奨）。Editorial Grid の印刷物らしい見出しの階層を参考にする
- Astro の scroll-driven animations については、スタックのガイドラインに該当が無かった（一般の指針で判断した）
