# サイトの作り直し（段階②-a）

## 目的
表は30秒で読める普通の自己紹介のまま、その下に「このサイトそのものが作り方の証拠」になっている層を置く。人事はスマホで最初の画面だけで何者か分かり、面接官は気になった場所から、その部分を決めた PR・ADR・コードまで降りられる。

### Non Goals
- 配信基盤の移行（段階②-c）
- `/infra` の構成図と稼働状況（段階②-d）
- 毎日自動で書き換わる数字（アイデアソンの案42は採らない）
- 閲覧の記録を本人に返す仕組み（案17・18は採らない）

## 背景
- 段階①で中身と最初の画面を作り直した（→ [トップページ（段階①）](./top-page.md)）
- アイデアソンの記録: [デザイン](../ideathon/2026-10-15-design.md)・[スクロールで動く場面](../ideathon/2026-10-15-scroll-scene.md)（動く場面は 2026-10-23 に外した）
- About に置くものは grilling で決めた（→ [ADR-008](../adr/adr-008-goal-visibility.md)・[About の仕様](../superpowers/specs/2026-10-23-about-design.md)）
- 「この部分の作り」に出す PR は、main の squash のコミットの件名の末尾 `(#N)` から、ファイルごとの `git log` で拾える。GitHub の API は使わない

## 概要
見た目は「リングノートから破り取ったページを、のりで台紙に貼った形」にする。セクションごとに1枚の紙を順に貼り、縦にスクロールして読んでいく。白い紙に水色の罫線を引き、文字は罫線の上に書く。箱や札は使わず、強調は蛍光ペン。トップは1枚のまま、最初の画面 → 経歴 → 作品 → スキル → About → リンクの順を保つ。

各セクションの右下に「この部分の作り」を置く。開くと、そのセクションを決めた ADR、コードのファイル、そのファイルを変えた最近の PR 3件が出る。JS は使わず `<details>` で作る。ブログの記事の末尾にも「この記事の履歴」を置く。

About には経験の事実だけを、時期と一行ずつの年表で並べる。読んだ人が本人に聞きたくなったときのために、リンクの紙に「話しかけるなら X の DM へ」を置く。

作品ごとのページ（`/works/<名前>`）を作り、面接官が掘る入口にする。本番の前に見た目を確かめるため、PR ごとの確認用の環境（staging）を用意する。

## 設計詳細

### 利用者と主タスク
- 人事: スマホで30秒〜1分。最初の画面で名前・所属・実績3つを読み、読み終えたら社内に回す
- 現場のエンジニア: PC で10〜20分。気になった場所の「この部分の作り」や作品ページから、判断の根拠を掘る
- 自分: PR を出し、staging で見た目を確かめてから merge する

### 画面と遷移

**トップ（`/`）**
1. 最初の画面: 名前・所属・実績3つ・評価・リンク（段階①の中身のまま）
2. 経歴
3. 作品: カード全体が作品ページへのリンク
4. スキル
5. About: 経験の年表
6. リンク: 外部リンク、社内転送用の一行、AI エージェント向けの説明

各セクションの右下に「この部分の作り」（`<details>`）。

**About の年表**（→ [About の仕様](../superpowers/specs/2026-10-23-about-design.md)）
- 経歴の紙と同じ日付の欄（`.margin-note`）に時期を書き、一行ずつ事実だけを書く。時期は「小学校〜高校」「2024」「2025」「大学」の4つ
- 「大学」の下に、競技プログラミング（AtCoder の色は最初の画面と同じ `ratings` から）、Neovim と Nix、マシンごとの OS の遍歴を並べる
- 自分の評価（性格・好き・楽しい）は書かない

**作品ページ（`/works/<名前>`）**
- 上に「作品一覧に戻る」（トップの該当カードの位置へ）
- 順番: 何を作ったか・誰のためか → 自分の役割 → 結果 → 判断（技術選定とその理由、捨てた案）→ リンク（GitHub・デモ）→ この部分の作り
- 中身の無い項目は見出しごと出さない
- 文章は、事実を確かめてから書く。各作品のリポジトリ（README・コミット）で確かめ、確かめられないことは書く前に本人に聞く。チームの作品での役割は、本人が決める

**ブログ**
- 一覧と記事は新しい見た目に合わせる。URL は変えない
- 記事の末尾に「この記事の履歴」（記事のファイルを変えた PR）

**AI エージェント向けの説明**
- `/llms.txt` をビルド時に `src/data/` から作る
- リンク欄に「AI エージェント向けの説明」として `/llms.txt`、リポジトリの `CLAUDE.md`・`docs/` へのリンクを並べ、AI エージェントもこのリポジトリの開発者であることを一言添える

**社内転送用の一行**
- リンク欄に「共有」ボタン。スマホは共有シート（`navigator.share`）、PC は文をコピー
- 文面は `src/data/profile.ts` の要約から作る: 「藤井 優気（28卒・公立はこだて未来大学）Go College ベストエンジニアリング賞・ハッカソン受賞3回・ICPC 2025 横浜 https://wisteria-io.com」

**staging**
- このリポジトリから出た PR（fork でないもの）は、verify が通ったら `staging.wisteria-io.com` に出す。最後に verify を終えた PR で上書きする
- staging は検索に載せない（noindex）
- fork からの PR は、今まで通り自宅の機械で動かさない

### 一覧
- 作品カード: カード全体が作品ページへ。並び替え・絞り込みは5件のため置かない
- ブログ一覧: 今の並び（新しい順）のまま

### 入力
- 入力欄は無い。ボタンは「共有」だけ

### 状態
- 静的なページのため、読み込み中・エラー・権限なしは対象外
- 「この部分の作り」で PR がまだ無い: 「まだ変更の記録がない」と出す
- 作品ページで項目の中身が無い: 項目ごと出さない
- JS が無い: 「共有」ボタンの代わりに文そのものを出す

### 見た目
- テーマは大学ノート。理由（本人が決めた）は2つ
  - 考え続け、考えたことを言葉にして残す（根底は考える葦）。ノートは考えたことを書き残す場所
  - 大学で学び、書き留めながら考えている今の自分を表す
- テーマから外れる部品を置かない。前の「紙」案は罫線が飾りで、角の丸い箱や札が混ざり、ノートに見えるのにノートではない部分が多かった
- 紙と線
  - 白に近い紙に水色の罫線。赤い余白線は引かない（日本の大学ノートには無い）
  - ページの上に「Date」（最後に更新した日）。記事は「No.」（何本目の記事か）と書いた日
- 幅ごとの頁
  - スマホ（〜767px）: 日付は本文の上の行
  - タブレット（768〜1023px）: 日付は本文の左の日付欄。記事の紙は日付欄を取らず、本文を中央に置いて少し細くする
  - PC（1024px〜）: タブレットと同じ。紙を広めにする
  - どの幅でも、セクションごとに1枚の紙。紙の上の端はリングから破り取った跡（穴のところのちぎれと、間の切れ端）。リング・ミシン目・テープは描かない。紙と紙の間に台紙。紙の高さは中身に合わせる
  - 罫線の間隔は本文の行の高さ（28px = 16px × 1.75）にそろえ、文字を線の上に乗せる
  - 記事も同じノートにする。コードはノートに貼った印刷物として、暗い箱のまま
- 部品の置き換え
  - 作品のカード → 箱をやめ、罫線の上に直接書く。作品の間は1行空ける
  - 受賞・実績 → 蛍光ペンの線
  - 技術のタグ → 「Python・Flask・FastAPI」と1行で書く
  - 経歴の年表 → 日付を日付欄（タブレット）か本文の上の行に書く
  - GitHub・X・AtCoder へのリンク → 紙に貼ったシール（白い縁の型抜き、少し傾ける）。文中のリンクは下線
  - 作品の受賞 → 朱色の判子を題の横に押す
  - 「この部分の作り」 → 余白に書き足したメモ。前の判断は取り消し線で残す
- 色
  - 文字は黒、リンクは青のボールペンの色、蛍光ペンは黄色（staging で藤色と見比べて決めた）
- 押せる高さ: 実績やリンクは 24px 以上（WCAG 2.5.8 の AA）にして空行を挟まない。ナビは 44px 以上
- 書体: 本文はゴシック（日本語は端末のフォント、ADR-009）。英字だけ手書きの書体（Caveat）にし、紙の上の欄に書き込む番号と日付、英語のセクションの見出しに使う。見出しには蛍光ペンを引く。落書きは描かない（学生の自由帳に見せない）
- 明るい紙だけにし、ダークは作らない
- 動き: 貼った紙は動かさない。セクションが浮き上がる動きはやめる

## 検討した別の選択肢
- **生成りの紙に罫線と藤色（前の案）**: 罫線が飾りで文字が線に乗らず、箱や札が混ざって「AI っぽい」「色が合わない」と言われた
- **校正刷り（組まれた文書に赤字）**: 判断が変わった跡は表せるが、編集の仕事を知らない人には何の絵か伝わりにくい
- **研究ノート・方眼ノート**: 記録の決まりは ADR と重なるが、ノートだと分かるまでに一拍かかる
- **葦と藤（育つもの）・台本や譜面**: 植物の絵は飾りになりやすく、台本や譜面は比喩の説明が要る
- **スイス・ミニマル（白地・黒の罫線・等幅の見出し）**: 表が一番普通に見えるが、角張った線が初期表示のように見え、作っていない印象を与える
- **今の暗い配色の延長**: 無難だが、よく見る形
- **About に人生の KGI・KSF・KPI の樹形図とスクロールで動く場面を置く（前の案）**: 性格や価値観を語りすぎて痛く見え、聞きたい余白も残らない（→ ADR-008）
- **スクロールでスライドのように1画面ずつ切り替える**: 1画面に収まらないセクションが読めなくなり、30秒で流したい人事の邪魔になる
- **「この部分の作り」を全体のスイッチで出す**: JS が要り、最初の画面を選ばせる手間も増える
- **About を別ページにする**: 人事が読む前に離れる
- **develop ブランチで staging を作る**: squash で merge するたびに履歴がずれ、衝突しやすくなる

## 注意点・懸念事項
- 紙の地と蛍光ペンの上での文字のコントラスト（4.5:1）を、`pnpm test` の計算と Lighthouse で確かめる
- 罫線に文字を乗せるため、行の高さを変える部品（大きな見出し・画像）も罫線の間隔の倍数にそろえる
- CI のチェックアウトを深くし（`fetch-depth: 0`）、ファイルごとの PR を拾えるようにする。ビルドが少し遅くなる
- scroll-driven animations は Firefox が既定で未対応。未対応でも最後の状態が出るので、中身は欠けない
- 作品ページの文章は、チームの成果を自分の成果として書かない
- インターン先の社内のことは書かない

## Pro Max 参照
- E-Ink / Paper: 白に近い紙に黒い文字の高いコントラスト、読むことに絞って飾りの部品を減らす、印刷しても崩れない
- Line Height（Medium）: 本文の行の高さは 1.5〜1.75。罫線の間隔を 28px（16px × 1.75）にする
- Heading Line Balance（Medium）: 短い見出しは `text-wrap: balance` で行の長さをそろえる
- Reduced Motion（High）: `prefers-reduced-motion` を確かめ、動きを止める
- Touch Target Size（High）: Web は WCAG の Target Size に従う。隣接するリンク・チップの間隔は 8px 以上（段階①から継続）
- Contrast Readability（High）: 明るい地には濃い文字。灰色の地に灰色の文字を置かない
- Heading Line Balance（Medium）: 見出しの改行を `<br>` で固定せず、幅とフォントを変えて自然な折り返しを確かめる
- スタイル: E-Ink / Paper（ダークは非推奨）。Editorial Grid の印刷物らしい見出しの階層を参考にする
- Astro の scroll-driven animations については、スタックのガイドラインに該当が無かった（一般の指針で判断した）
