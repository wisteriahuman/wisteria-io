# トップページ（段階①）

## 目的
スライドやイベントの QR からスマホで来た人事が、30秒で何者か・主な実績を言える状態にする。

### Non Goals
- デザインの刷新（段階②でアイデアソンを経て決める）
- 作品ごとの詳細ページ
- インフラ・配信方式の変更
- 人生の目標の構造（文言が未決のため段階②）

## 背景
- 2026-10-17 のサポーターズのイベントでスライドから来る人が多い。スマホで開く前提
- 既存トップの最初の画面には実績が1つもなく、「Software Engineer」「開発と競プロが好きです」だけだった
- トップページに OGP 画像がなく、URL を共有すると画像なしのカードになる
- 要件は [requirements/README.md](../requirements/README.md)、対象のストーリーは US-01・US-02・DS-02 を参照

## 概要
最初の画面に、名前・所属・実績3つ・競技プログラミングの評価を収める。姿勢を書いた一行は置かず、事実だけで何者かを伝える。

セクションは人事が上から読む順に並べ替える。実績を前に、自己紹介を後ろに置く。

トップページ用の OGP 画像を新設し、ブログの OGP も同じデザインに揃える。

## 設計詳細

### 利用者と主タスク
- 人事：スマホで30秒〜1分。何者か・実績・人柄を知り、次の選考に進めるか判断する
- 現場のエンジニア：PC で10〜20分。段階①では既存の作品リンクから GitHub を掘る

### 画面と遷移

最初の画面（スマホで1画面に収める）:

```

[Go College ベストエンジニアリング賞] [ハッカソン受賞3回] [ICPC 2025 横浜]
```

- 実績のチップは押すと経歴セクションの該当項目へ移動する
- アイコン画像は小さくし、最初の画面の高さを実績に使う
- 学年は書かず「28卒」とする。卒業年は変わらないため更新が要らない

セクションの順番:

1. 最初の画面
2. 経歴（インターン・受賞・ICPC）
3. 作品（ハッカソン4件と FUN Developers Hub）
4. スキル
5. About
6. リンク・ブログ

ナビゲーションも同じ順に並べ替える。

実績のデータ（→ [DS-02](../requirements/developer-stories.md#ds-02-実績を1か所直せば全体に反映される)）:
- 受賞・インターン・大会の実績を1つのデータファイルにまとめる
- 最初の画面のチップ・経歴セクション・トップページの OGP は、すべてこのデータから作る

作品:
- ハッカソン4件と FUN Developers Hub（学内演習のチーム開発）。yajiuma.nvim は載せない
- FUN Developers Hub は、Go を使った唯一の作品で、今も続いているチーム開発のため残す
- カードの行き先は従来どおり GitHub・関連サイト

About:
- 「3年」の記述を削除する
- 環境の記述を現状に合わせ、マシンごとの OS の遍歴を書く（Surface は今 Ubuntu Server）

### OGP
- トップページ: 名前・所属・実績3つ・評価を載せた画像を satori で生成する
- ブログ: 同じデザインに揃える（記事タイトル＋サイト名）
- title: `藤井 優気 (wisteria) | ポートフォリオ`
- description: 所属と実績3つを並べた文（例: `28卒・公立はこだて未来大学。Go College ベストエンジニアリング賞・ハッカソン受賞3回・ICPC 2025 横浜`）

### 状態
- 静的ページのため、空・読み込み中・エラーは対象外

### 見た目
- 既存のダークデザインを保つ
- 受賞表示の絵文字（🏆）は SVG アイコンに置き換える

## 検討した別の選択肢
- **「Go でバックエンドを書く」を一行にする**: 事実だが言語に縛られ、本質（課題発見から実行まで）を取りこぼすため不採用
- **姿勢だけの一行（「設計から基盤まで」等）**: 根拠がなく読み飛ばされるため不採用
- **姿勢を動詞で書いた一行（「課題を見つけ、技術を選び、作りきる。」）**: 一度は採用したが、外した。動詞を3つ並べる言い回しも AI の文に多く、自己紹介で一言の標語を言う場面もない。名前・所属・実績だけで何者かは伝わる（2026-10-15）
- **AtCoder・paiza の評価をチップにする**: チップが5つになると、主な実績3つの重みが薄れる。チップの下に小さく1行で置く
- **ビジュアルで何者かを示す**: 効果は大きいが、何を見せるかにアイデアソンが要るため段階②へ
- **yajiuma.nvim を作品に載せる**: 人事が最初に見る場所でネタ作品は評価軸をぶらすため見送り

## 注意点・懸念事項
- 最初の画面がスマホ（幅 375px 前後）で1画面に収まることを実機幅で確認する
- OGP 画像のフォントは Google Fonts からビルド時に取得している。ビルド環境がネットに出られない場合に失敗する
- Lighthouse（モバイル）4項目100を目標に、変更後に計測する

## Pro Max 参照
- タッチ領域: Web は WCAG の Target Size に従い、隣接するリンク・チップの間隔は 8px 以上
- アイコン: 絵文字をアイコンとして使わず SVG にする
- 画像: ローカル画像は `astro:assets` の `<Image />` で最適化する
- ポートフォリオの構成: 名前・役割 → 作品 → 人物 → 連絡先の順を基本とし、本件では人事向けに実績を作品より前に置く
